Void Explorer 有 2048 个星系，上万颗程序化生成的星球，其中不少跟地球一样大。你可以从远处挑一个光点飞过去，穿过大气层，降落在海岸边，跳下船在陆地上走走，再开船飞回来。作者 Thomas Ricouard 用 Astra 做了这个。原文发在 OpenAI Developers 博客上。

这篇文章有意思的地方不在于"AI 能做游戏了"。2048 个星系、真实距离、连续降落、程序化地形流送，这些是硬核技术挑战。Astra 的价值在于把这些挑战的决策链路压短了。下面按他原文的顺序，说说几个关键节点。

## 先描述体验，不要先描述技术

他的第一版需求描述很朴素，大意是，目之所及皆可抵达，距离要真实，通过速度和缩放让旅行可行。想从太空飞进大气层落到地面。星球可以大到地球那么大的程度，所以需要程序化地形和分块渲染器。

这段描述看起来简单，但它直接把渲染、地形、飞控三个方向框死了。一颗星不能是背景贴图上的点，必须可导航。一颗星球不能在接近时切换成另一个关卡，必须连续过渡。旅行距离要真实，得用虚构的脉冲旅行和曲速引擎让距离可行。

他还在写游戏之前就用了图片生成。先让模型出概念图，来回几轮找到对的感觉。第一轮太写实，第二轮太简单。他给了一轮具体修正，要中间地带，更好的颜色，霓虹光感，更深的空间对比，还要高速飞行时星星和尘埃的效果。满意的图出来后，他让 Astra 把这些方向存下来当后续参照。

这个顺序很重要。图片先行，视觉方向先定，后面每一个实现判断都有了标杆。

## 架构选型交给 Astra

技术栈是 Astra 建议的。TypeScript + Vite 做应用框架，Three.js 做渲染，地形生成跑在 Web Workers 里不卡主线程，Vitest 测逻辑，Playwright 测浏览器实际表现。

他用过一个 WebGL2 的原型，后来问 Three.js 是不是限制了画面质量。Astra 建议保留仿真层，把渲染器切到 Three.js 的 WebGPU 架构。仿真、导航、地形系统全保留，只换渲染层。

渲染器用 Three.js 的 node materials 和 Three.js Shading Language 在代码里定义大气、水面和光照效果。这套选择意味着大部分视觉工作都落在代码里，不依赖外部资产。

## 留一个检查口

Astra 需要能独立排查问题的能力，不能每次只靠作者口述。游戏暴露了一个 `window.__VOID_EXPLORER__` 接口，浏览器测试可以调用它查看当前状态，包括接近的天体、飞行模式、地形就绪状态、活动摄像机。还能看渲染和流送计数器，draw calls、三角形数、排队中的地形任务、已缓冲的地形数据。

游戏有几个命名的测试场景，轨道、脉冲旅行、大气层下降、海岸着陆。Astra 回到这些场景不用每次都飞遍整个宇宙。Playwright 加载场景，等地形就绪，截图，检查状态。独立的旅程测试用真实操控录制位置和状态变化，确保设置好的着陆场景不替代着陆本身。

测试覆盖了着陆、下船、步行、存档读档、登机、起飞。能抓到截图发现不了的问题，比如碰撞面没准备好，或者飞船在过渡时跳位置。

他还能让 Astra 直接检查他正在玩的那个浏览器标签。问他 Aurelia 的云上还能看见吗，Astra 截屏并读取屏幕上的飞行信息。这些是特定点的检查，不是持续监控每一帧。

## 尺度问题不能靠一个坐标系硬扛

光年距离和一个人站在船边，不能用同一套坐标。把巨大的位置直接送 GPU，靠近地面时会丢失精度。

Astra 把物理地址和渲染位置分开了。宇宙用大整数单元格加局部偏移量。渲染前减去观察者位置，摄像机永远在原点，附近物体坐标保持小值，精度不丢。显示距离和相对大小保持一致。

动态物体也需要在时间上对齐。星星、行星、卫星走解析轨道，渲染器在同一仿真时间评估它们相对于观察者的位置。停在行星上的船随行星自转。星星的位置和颜色驱动光照，所以从轨道看到的两颗太阳，到地表还是那两颗。

## 连续降落最难

从太空到地面的过渡是迭代最多的地方。他描述了一个具体场景，接近行星时几乎平行，速度仍然偏快，行星在地形加载时几乎消失。需要同时修速度曲线和地形流送。大气层能不能软化远处 LOD 和详细地形之间的过渡？行星在接近过程中不能消失。

飞控现在给近平面接近单独加了速度上限，基于海拔和行星半径与重力的轨道速度估计。靠近地面还会采样前方地形来调整刹车。

游戏用多层 LOD。远处星球是一个廉价的六面投影球。随着它占据更多屏幕，渲染器加细节。接近表面时激活基于六面投影球构建的地形。每一面可以递归拆成四个小方块，这就是四叉树。这样能在可见区域和前进方向精细地形，而不必在整个地球尺寸上做步行级分辨率。

近地面用局部网格在飞船和玩家周围补充更精细的几何体。所有这些表示采样同一个底层星球。一个共享函数合成大陆、山脉、陨石坑和更小尺度的起伏，提供海拔、水体、生物群落等信号。粗糙和精细网格在不同分辨率下近似这些数据，共享颜色策略保持行星外观一致。

交接和生成一样重要。远处的星球一直可见，直到六个粗糙地形面全部就绪。一块瓦片一直保留，直到四个子块全部就绪。过渡期间用互补像素遮罩把每个像素分配给旧表面或新表面，整个星球不会在替换加载时变透明。

## 慢帧先量化再改

他给 Astra 的反馈经常同时涉及外观和性能，因为同一趟飞行里两个问题都看到了。他问能不能看看从太空飞向地面时星球是怎么加载和渲染的。远处的球体和详细地形看起来不一致，过渡很突兀，尤其颜色变化时。想理解这些视觉跳跃的原因，以及哪里能减少加载细节的工作量。

Astra 用 Three.js 的渲染器计数器检查 draw calls、三角形、几何体、纹理数。一个 Playwright 测试采集 90 帧间隔，报告平均和百分位计时，加上这些计数。视觉问题还能对比某个效果开和关时的渲染像素差异，比如遮罩开和关时地形。这帮他隔离了为什么地面会消失，而不是只靠一张坏场景的截图。

一次飞船模型替换很有代表性。他问能不能看看加载和渲染过程中实际发生了什么。Astra 检查了生成了多少几何体、多少数据在 worker 和渲染器之间传输、地形任务在被丢弃前发生了什么。

其中一个改动是按星球在屏幕上的大小分配远处细节。占满屏幕的星球需要立刻有好的轮廓，小到一像素的星球不需要同样的几何体。一个受控起始场景对比中，新策略用了 7040 个代理三角形，替代了原来的 51200 个。两种策略用同一个几何体生产者，所以隔离的是加载决策本身。

另一个改进用了完全相同数量的地形三角形。索引网格复用相邻三角形共享的顶点，位置、颜色、法线数据不必重复传。测试中的六层地面在高画质下，传输缓冲区从约 35 MB 降到 15 MB，保留了 241952 个三角形。地面和装饰物也拆成独立任务，地面几何体能就绪而不必等装饰物。

地形选择器里有浪费。它会请求块，改变决策，丢弃，再请求替代品。Astra 稳住了细化决策，只在预算允许时细化瓦片。受控仿真中，固定 worker 延迟、6 秒下降加 3 秒稳定，废弃任务从 6074 个降到 13 个。

Worker 不能解决所有卡顿。主线程的地形回退也需要让出。Astra 把生成拆成可恢复的步骤，每帧预算约 4 ms，大型地形任务不用一口气跑完。渲染器还单独限制世界分辨率和界面分辨率，低画质时导航文字保持锐利。

## 概念图变资产

宇宙大部分是代码生成的，星球、地形、云、环、星星。玩家飞船是主要的自制 3D 资产，他用了不同方法。

先用生成的概念图和 Blender 渲染审阅飞船，再放进游戏。翅膀不对时，他要求更多有用的参考。让模型从多个角度出干净视图，注意前后翅膀，会用来重做 3D 模型。他选了四个独立翅膀、对称造型、翼尖有粉色灯光的那个版本。然后让 Astra 在 Blender 里建新模型，保持游戏的艺术风格，加进游戏。

这涉及把参考变成几何体，审阅轮廓和材质，准备运行时资产。Blender 源文件有 193 个可编辑网格，导出的飞船有 14898 个三角形，分组到 8 个不透明材质批次。他可以在模型里要求细节，Astra 把导出的渲染成本控制在可接受范围。

## 水也是代码生成的

Sunwake 里他在一个用小型船在程序化海洋上航行的游戏，想要棱面波浪、平滑运动和彩色玻璃的颜色。Astra 在 Three.js 里做了自定义水面渲染器，同一个波浪模型同时驱动可见水面和船的浮力。船体随波浪升沉、前后倾、左右摆，局部仿真处理涟漪和泡沫，船留下航迹和飞沫。后来他又让 Astra 在 Blender 里做更精细的船再导入游戏，和 Void Explorer 同一个模式，程序化环境加自制载具，通过仿真连接。

Hollowflux 是另一个方向，一个围绕发光地下河流的小型 2D 动作 RPG。洞穴、角色、装备全在代码里画，不用导入精灵表。他不断要求 Astra 让走动、冲刺和攻击更真实地搅动水面。一个网格跟踪水高、水流、泡沫和电荷。脚步留下涟漪，矛刺开窄航迹，锤击扩散波纹。水流沿河岸卷曲，带泡沫向下游流，同一流动推动玩家和敌人。水还影响战斗，鳗鱼的放电通过连通水体传导，踩上干石头就能躲避那道放电。

## 最后一步很简单

Astra 有个 Sites 插件，一句话就能部署游戏分享出去。他说让 Astra 用 Sites 部署这个游戏并给个链接，公开访问，任何人都能在浏览器里直接玩。

他提了一个建议，手上如果有游戏点子，从一个小的能玩的东西开始就行。一艘船、一个房间、一段手感。玩一玩，给具体反馈，然后继续搭。

原文在 OpenAI Developers 博客上，Thomas Ricouard 写的。Void Explorer、Sunwake 和 Hollowflux 三个游戏都给了在线可玩的链接。
