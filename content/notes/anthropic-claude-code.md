> 原文：[How Anthropic teams use Claude Code](https://claude.com/resources/articles/how-anthropic-teams-use-claude-code)
> 作者：Anthropic　|　分类：最佳实践　|　产品：Claude Code
> 发布日期：2025 年 7 月 24 日　|　阅读时间：约 9 分钟

Anthropic 内部各个团队都在使用 Claude Code，用途五花八门：排查线上问题、摸索陌生的代码库、搭建自定义的自动化工具，等等。下面就是他们的实际用法。

---

像 Claude Code 这样的智能体式编程（agentic coding）工具，能帮助开发者加快工作流、把重复性任务自动化，并攻克复杂的编程项目。随着这个领域不断发展，我们每天都在从用户——包括我们自己的员工——身上了解到新的应用场景。

为了深入了解，我们找了几位 Anthropic 的员工聊了聊，看看他们在工作中是怎么用 Claude Code 的。

他们的很多用法都在意料之中——调试、熟悉代码库、管理工作流；但也有一些让我们眼前一亮：法务团队搭起了电话转接（phone tree）系统，市场团队几秒钟就能生成上百条广告文案变体，数据科学家在完全不懂 JavaScript 的情况下做出了复杂的可视化图表。

其中的规律渐渐清晰：智能体式编程并不只是在给传统的开发提速，它正在打破"技术"与"非技术"工作之间的界限，让任何一个能把问题讲清楚的人，都变成一个能把解决方案做出来的人。

以下就是我们的收获。

## 代码库的导航与理解

公司各个团队都用 Claude Code 来帮助新人和老员工更快地摸清我们的代码库。

基础设施团队新来的数据科学家，会把整个代码库喂给 Claude Code，以便快速上手。Claude 会读取代码库里的 `CLAUDE.md` 文件，找出相关的部分，讲清数据管道（data pipeline）之间的依赖关系，并说明哪些上游数据源汇入了哪些看板（dashboard），从而取代了传统的数据目录工具。

产品工程团队把 Claude Code 当作任何编程任务的"第一站"。他们会先让 Claude 指出：要修 bug、做功能或做分析，该去看哪些文件。这就省去了在动手之前手动收集上下文的那段耗时流程。

## 测试与代码审查

智能体式编程工具之所以特别受欢迎，很大程度上是因为它能自动化两件关键却繁琐的编程任务：写单元测试和做代码审查。

产品设计团队用 Claude Code 为新功能编写全面的测试。他们通过 GitHub Actions 实现了 Pull Request 评论的自动化，由 Claude 自动处理格式问题并重构测试用例。

安全工程团队则把工作流从过去那种"设计文档 → 潦草的代码 → 重构 → 干脆放弃写测试"，转变为：先让 Claude 写伪代码（pseudocode），再引导它走测试驱动开发（TDD）的流程，并定期检查进度。这样产出的代码更可靠、也更好测。

智能体式编程还能用来把测试"翻译"成别的编程语言。比如，推理（Inference）团队需要在 Rust 这类自己不熟悉的语言里测试功能时，只需说明想测什么，Claude 就能用代码库本身的原生语言把逻辑写出来。

## 调试与排障

线上问题往往需要尽快解决，可在压力之下硬啃陌生的代码，常常只会拖慢进度。对公司的许多团队来说，Claude Code 能实时分析堆栈跟踪（stack trace）、文档和系统行为，从而加快定位和修复的速度。

在故障处理过程中，安全工程团队会把堆栈跟踪和文档喂给 Claude Code，让它顺着代码库追踪控制流。以前要靠人工翻查 10 到 15 分钟的问题，如今解决速度快了 3 倍。

有了 Claude Code，产品工程团队也有底气去搞定那些陌生代码库里的 bug 了。他们直接问 Claude："你能修一下这个 bug 吗？我看到的现象是这样的"，然后审查它给出的方案，而不必再去求助其他工程团队。

有一次，Kubernetes 集群不再调度 Pod 了，数据基础设施团队用 Claude Code 来诊断问题。他们把看板的截图喂给它，Claude 便带着他们在 Google Cloud 的界面里一项项菜单地排查，最终定位到是 Pod 的 IP 地址耗尽了。随后 Claude 给出了创建新 IP 池并将其加入集群的准确命令，为他们在系统宕机期间省下了宝贵的 20 分钟。

## 原型设计与功能开发

按传统方式开发新功能，既需要深厚的技术功底，又要投入大量时间。而 Claude Code 让快速出原型、甚至完整开发一个应用成为可能，让各个团队能够迅速验证想法，无论编程水平高低。

产品设计团队的成员会把 Figma 设计稿喂给 Claude Code，然后设置一个自动循环：由 Claude Code 编写新功能的代码、跑测试，并不断迭代。他们把抽象的问题交给 Claude，让它自主工作，等方案出来后再做审查和最后的打磨。有一次，他们让 Claude 给自己实现了 Vim 键位绑定，几乎没怎么人工复核。

产品设计团队还从 Claude Code 中发现了一个意想不到的用法：把各种错误状态、逻辑流程和系统状态一一梳理出来，从而在设计阶段就发现边界情况（edge case），而不是等到开发阶段才暴露。这从根本上提升了他们的初始设计质量，也为日后省去了好几个小时的调试时间。

数据科学家虽然并不精通 TypeScript，却能借助 Claude Code 从零构建完整的 React 应用来可视化强化学习（RL）模型的性能。在沙箱环境里一次性写好提示词（prompt）后，这个工具就能凭空写出整套 TypeScript 可视化代码——哪怕他们自己完全看不懂。鉴于任务本身不复杂，如果第一次提示词效果不够好，他们只需稍作调整再试一次。

## 文档与知识管理

技术文档往往散落在各个 wiki、代码注释和团队成员的脑子里。Claude Code 借助 MCP 和 `CLAUDE.md` 文件把这些知识整合成易于获取的形式，让每个需要的人都能用上这些专业经验。

推理团队里没有机器学习背景的成员，依靠 Claude 来解释那些模型特有的函数。过去要花一小时在 Google 上搜个不停，现在 10 到 20 分钟就搞定了——研究时间减少了约 80%。

安全工程团队则让 Claude 摄取多个文档来源，生成 Markdown 格式的运维手册（runbook）和排障指南。这些精炼后的文档又能成为调试真实线上问题的上下文，往往比翻遍整个知识库效率更高。

## 自动化与工作流优化

智能体式编程工具能帮助团队搭建定制化的自动化流程，而这在传统上要么得占用专职开发资源，要么得买昂贵的软件。

增长营销团队搭建了一个智能体工作流，用来处理含有数百条广告的 CSV 文件，识别表现不佳的广告，并在严格的字符数限制内生成新的变体。借助两个专门的子智能体（sub-agent），这套系统只需几分钟而非几个小时，就能生成上百条新广告。

他们还开发了一个 Figma 插件，能识别画框（frame）并以编程方式自动生成多达 100 条广告变体——只需替换标题和描述即可，把过去几小时的复制粘贴压缩到了每批广告半秒钟。

还有一个相当独特的案例：法务团队做出了"电话转接"系统的原型，帮助同事在 Anthropic 内部找到对口的律师。这也说明，各部门完全可以在没有传统开发资源的情况下，自己动手做出合用的工具。

## 用 Claude Code 打开新的可能

这些故事揭示出一个规律：当你把重点放在 Claude Code 能增强的那些**人的工作流**上时，它才能发挥最大价值。最成功的团队是把 Claude Code 当作一个思考伙伴（thought partner），而不是一个代码生成器。

他们探索各种可能性、快速出原型，并在技术与非技术用户之间分享各自的发现。这种人与 AI 之间的协作方式，正在打开一扇扇我们才刚刚开始理解的机遇之门。
