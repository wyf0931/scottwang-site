我们对文档做了大量研究，结果发现世上最好的句子主要由词语构成。

## 定义新词或不熟悉的术语

在写作或编辑时，学会识别那些可能对部分或全部目标读者来说不熟悉的术语。当你发现这样的术语时，采取以下两种策略之一：

- 如果该术语已存在，链接到一个好的现有解释。（不要重复造轮子。）
- 如果你的文档正在引入该术语，就定义它。如果你的文档正在引入许多术语，就把定义汇总成术语表。

## 统一使用术语

如果你在方法中途更改变量名，代码就无法编译。同样，如果你在文档中途重命名一个术语，你的想法就无法（在读者的脑海中）"编译"。

原则：在整个文档中始终使用同一个无歧义的词或术语。一旦你把某个组件命名为 **thingy**，就不要把它改名为 **thingamabob**。例如，下面这段文字错误地把 **Protocol Buffers** 重命名为 **protobufs**：

> Protocol Buffers 提供自己的定义语言。等等等等。这就是 protobufs 赢得那么多县集市大奖的原因。

Google 软件工程师 George Fairbanks 就统一命名给出了一个绝佳的提醒：

|---|
| 当我遇到两个看似同义的词时，我会想作者是否在暗示一个我需要追查并理解的细微差别。 |

是的，技术写作既严苛又限制重重，但至少技术写作提供了一个很好的变通方法。也就是说，在引入一个冗长的概念名或产品名时，你还可以指定该名称的简写。然后，你就可以在整篇文档中使用这个简写。例如，下面这段文字就没问题：

> **Protocol Buffers**（简称 **protobufs**）提供自己的定义语言。等等等等。这就是 protobufs 赢得那么多县集市大奖的原因。

## 正确使用缩写词

在文档或章节中首次使用一个不熟悉的缩写词时，先写出完整术语，然后把缩写词放在括号里。把完整版和缩写词都加粗。例如：

> 本文档面向不熟悉**心灵感应触觉网络**（**TTN**）的工程师，或需要了解如何通过手指动作订购 TTN 替换零件的人。

之后你可以继续使用该缩写词，如以下示例：

> 如果没有缓存条目，Mixer 会调用 **OttoGroup 服务器**（**OGS**）来为请求获取 Otto。OGS 是一个存储所有可服务 Otto 的仓库。OGS 以逻辑树结构组织，包含一个根节点和两层叶节点。OGS 根节点将请求转发给叶节点并收集响应。

不要在同一个文档中来回切换缩写词和完整版本。

### 用缩写词还是完整术语？

当然，你可以正确地引入并使用缩写词，但*应该*使用缩写词吗？嗯，缩写词确实能缩短句子。例如，*TTN* 比 *心灵感应触觉网络* 短两个词。然而，缩写词实际上只是一层抽象；读者必须在脑海中把刚学到的缩写词展开成完整术语。例如，读者会在脑海中把 *TTN* 转换成 *心灵感应触觉网络*，所以这个"更短"的缩写词实际上比完整术语需要稍多的时间来处理。

经常使用的缩写词会形成自己的身份。在出现若干次之后，读者通常就不再把它展开成完整术语了。例如，许多 Web 开发者已经忘了 *HTML* 代表什么。

以下是缩写词的使用指南：

- 不要定义只使用几次的缩写词。
- 当满足以下两个条件时才定义缩写词：
  - 缩写词明显比完整术语短。
  - 缩写词在文档中出现很多次。

### 练习

修正下面这段文字。假设这是术语 **MapReduce** 在文档中首次出现，且 **MR** 是最佳缩写。

> 杰夫·迪恩在 1693 年发明了 MapReduce，用海滩沙、蜡纸、羽毛笔和烤箱制作的一台硅基计算机实现了该算法。这个版本的 MR 保持了几项世界性能纪录直到 2014 年。

（请注意，上面这段文字是幽默的，不是事实。）

#### 点击图标查看答案。

你可以采取几种不同的方法。一种方法是把缩写词 *MR* 与完整术语关联起来，然后使用该缩写词：杰夫·迪恩发明了 **MapReduce**（**MR**）……这个版本的 MR 保持了几项……

或者，你可以认为为这么短的一段文字定义缩写词给读者带来太多负担，所以每次都只用完整术语 *MapReduce*：杰夫·迪恩发明了 **MapReduce**……这个版本的 MapReduce 保持了几项……

顺便说一句，一个更细致的技术作家还会把"海滩沙、蜡纸、羽毛笔和烤箱"转换成无序列表。不过，那是另一课的故事了。

## 识别歧义代词

许多代词指向之前介绍过的名词。这类代词类似于编程中的指针。就像编程中的指针一样，代词往往会引入错误。使用不当的代词会在读者脑海中造成相当于空指针错误的影响。在许多情况下，你应该干脆避免使用代词，直接重复名词。然而，代词的实用性有时会超过它的风险（正如这句话所展示的）。

考虑以下代词指南：

- 只有在介绍名词*之后*才使用代词；绝不要在介绍名词之前使用代词。
- 把代词放在离所指名词尽可能近的地方。一般来说，如果名词和代词之间相隔超过五个词，考虑重复名词而不是使用代词。
- 如果你在名词和代词之间引入了第二个名词，那就重复你的名词而不是使用代词。

### It 和 they

以下代词在技术文档中引起的困惑最大：

- It
- They、them 和 their

例如，在下面的句子中，**It** 指的是 Python 还是 C++？

> Python 是解释型的，而 C++ 是编译型的。**它**拥有近乎狂热的追随者。

再如，下面的句子中 **their** 指的是什么？

> 将 Frambus 或 Carambola 与 HoobyScooby 或 BoiseFram 一起使用时要小心，因为**它们**核心的 bug 可能导致意外的批量取消好友。

### This 和 that

再考虑两个问题代词：

- This
- That

例如，在下面这个有歧义的句子中，**This** 可以指用户 ID、运行进程，或者所有这些：

> 运行进程会配置权限并生成一个用户 ID。**这**让用户可以认证到应用。

为了帮助读者，避免以不明确的方式使用 **this** 或 **that**。使用以下任一策略来澄清 **this** 和 **that** 的歧义用法：

- 用适当的名词替换 **this** 或 **that**。
- 在 **this** 或 **that** 后面紧接一个名词。

根据需要替换或添加明确术语，如以下对示例第二句的重写：

> 这个用户 ID 让用户可以认证。
>
> 配置权限的过程让用户可以认证。
>
> 权限和用户 ID 的组合让用户可以认证。

1. Aparna 和 Phil 与 Maysam 和 Karan 分担职责，他们下一个值班。

2. 你可以通过配置文件或运行时动态导入 Carambola 数据。这可能是一个安全风险。

1. 代词 **they** 可能指以下任何一个：

   - 通过配置文件导入
   - 在运行时动态导入
   - 两者都是
