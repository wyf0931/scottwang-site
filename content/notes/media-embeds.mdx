这篇文章介绍本站写作时可以直接使用的 Markdown 和 MDX 功能。它是站点使用说明，不是通用的 MDX 教程。示例都可以复制到 `content/writing`、`content/notes` 或 `content/thoughts` 下的文章里。

文章仍然以 Markdown 为主。只有需要受控组件时才使用 MDX，外部视频不要直接写 iframe，也不要在正文里加入任意脚本。

## 视频嵌入

博客提供了 `YouTubeEmbed` 和 `BilibiliEmbed` 两个组件，自动做响应式和 lazy loading，并在组件内部校验 provider URL。

YouTube 视频嵌入：

```mdx
<YouTubeEmbed url="https://www.youtube.com/watch?v=dQw4w9WgXcQ" title="示例 YouTube 视频" />
```

B 站视频嵌入：

```mdx
<BilibiliEmbed url="https://www.bilibili.com/video/BV1GJ411x7h7" title="示例 B 站视频" />
```

`url` 是必填参数。`title` 可选，用于无障碍标注，不填的话默认显示 "YouTube video" 或 "Bilibili video"。YouTube 同时支持 `youtube.com/watch?v=` 和 `youtu.be/` 两种链接格式，B 站支持标准的 BV 号 URL。

## 提示框 Callout

Callout 用来在文中插入需要读者注意的信息，渲染为带图标的 `<aside>` 块。

```mdx
<Callout tone="info">这是一条信息提示</Callout>
```

```mdx
<Callout tone="warning">这是一条警告提示</Callout>
```

```mdx
<Callout tone="success">这是一条成功提示</Callout>
```

<Callout tone="info">tone 的默认值是 info，所以不写 tone 也行。</Callout>

`tone` 支持三个值：`info`（默认）、`warning`、`success`。内容写在标签之间，可以包含行内 Markdown。

## Mermaid 图表

用 ` ```mermaid ` 开头的代码块会被自动渲染为 SVG 图表，客户端执行，支持暗色主题。

```mermaid
graph TD
title 示例流程图
    A[开始] --> B{判断条件}
    B -->|是| C[执行操作]
    B -->|否| D[结束]
```

上图的源码如下：

````mdx
```mermaid
graph TD
title 示例流程图
    A[开始] --> B{判断条件}
    B -->|是| C[执行操作]
    B -->|否| D[结束]
```
````

支持 Mermaid 常用图表类型，包括 graph、sequence、class、state、er、gantt、pie 和 packet。用 `title` 关键字在图表定义内写标题。

## 代码高亮

所有代码块通过 rehype-pretty-code 渲染，自动带上语法高亮和复制按钮。写法就是标准 Markdown 代码块，语言标识决定高亮方案：

```typescript
const greeting = "Hello, MDX!";
console.log(greeting);
```

````mdx
```typescript
const greeting = "Hello, MDX!";
console.log(greeting);
```
````

支持的语言标识跟 Shiki 一致，常见的 `javascript`、`typescript`、`python`、`rust`、`go`、`bash`、`json`、`yaml` 等都能识别。

## GitHub 项目卡片

GitHub 项目卡片可以放在正文任意位置，适合放在资源、工具介绍或项目分析的结尾。它读取构建时缓存的仓库信息，显示 GitHub 图标、仓库头像、仓库名、项目描述、Stars、Forks、主要语言和 GitHub 入口。

```mdx
<GithubRepoCard repo="lexiforest/curl_cffi" />
```

组件的 `repo` 必须使用 `owner/repo` 格式：

```mdx
<GithubRepoCard repo="acornjs/acorn" />
```

`github: "owner/repo"` 仍可保留在 frontmatter 中，用于兼容旧内容和构建缓存，但不会自动在文章底部追加卡片。构建时如果 GitHub API 不可用，站点会优先使用已有缓存，首次没有缓存时仍保留仓库链接。
