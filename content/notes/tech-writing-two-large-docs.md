如何把一大片信息组织成一份连贯的文档或网站？反过来，如何把一个杂乱无章的现有文档或网站重组得易于接近、切实有用？以下策略可以帮到你：

- 选择撰写一份大型文档，还是撰写一组文档
- 组织文档
- 添加导航
- 渐进式披露信息

## 何时撰写大型文档

你可以把一片信息组织成一份较长的独立文档，或者一组较短的相互关联的文档。一组较短的相互关联的文档通常以网站、wiki 或类似结构化格式发布。

有些读者比其他人更能接受较长的文档。请考虑你为之撰写文档的两位假想读者的视角：

- Hong 觉得阅读长文档很吃力、容易迷失方向。他更喜欢用站内搜索来找到问题的答案。
- Rose 可以轻松地在大型文档中穿行。她经常使用浏览器内置的页面内搜索功能来查找当前页面的有用信息。

那么，你应该把材料组织成一份文档，还是组织成网站中的一组文档呢？请考虑以下准则：

- 面向对主题完全陌生的读者时，"如何做"指南、入门概览和概念指南通常以较短的文档形式效果更好。例如，一个对你主题完全陌生的读者可能难以记住大量新术语、新概念和新事实。记住，你的读者可能是为了快速、宽泛地了解主题而阅读你的文档。
- 深度教程、最佳实践指南和命令行参考页，以较长的文档形式效果很好，尤其是面向对工具和主题已有一定经验的读者时。
- 一份优秀的教程可以依靠叙事，在一份较长的文档中引导读者完成一系列相关任务。不过，即便是大型教程，有时也能从拆分成更小的部分中受益。
- 许多较长的文档并不适合一次性读完。例如，用户通常会扫读一个参考页，来查找某个命令或标志的说明。

本单元的其余部分将介绍对撰写较长文档（例如教程和一些概念指南）有用的技巧。

## 组织文档

本节建议了一些规划较长文档的技巧，包括创建大纲和起草引言。完成文档初稿之后，你可以对照你的大纲和引言来审阅它，以确保没有遗漏你原本打算覆盖的内容。

### 为文档编写大纲

从结构化的高层大纲入手，可以帮助你归组主题，并确定哪里需要更多细节。大纲帮助你在动笔之前移动主题的位置。

你可能会觉得把大纲看作文档的叙事会很有用。编写大纲没有标准方法，但以下准则提供了一些可能对你有用的实用提示：

- 在你要求读者执行一项任务之前，先向他们解释为什么要做这件事。例如，以下要点展示了一份关于审计和改进网页无障碍性的教程中大纲的一节：
  - 介绍一款审计网页无障碍性的浏览器插件；解释读者将用审计报告的结果来修复几个 bug。
  - 列出运行该插件并审计网页无障碍性的步骤。
- 把大纲的每一步限定为描述一个概念或完成一项具体任务。
- 把你的大纲组织成：文档在信息与读者最相关时介绍它。例如，当读者刚开始学习基础知识时，他们大概不需要（也不想知道）文档开头部分中项目的历史。如果你觉得项目的历史有用，那么在文档末尾加入指向这类信息的链接。
- 考虑先解释一个概念，然后演示读者如何在一个示例项目或他们自己的工作中应用它。在概念性信息和实践步骤之间交替的文档，可以是一种特别有吸引力的学习方式。
- 在你开始起草之前，把你的大纲分享给贡献者。如果你与一支将要审阅和测试你文档的贡献者团队合作，大纲尤其有用。

### 介绍一份文档

如果你的文档读者在主题中找不到相关性，他们很可能会无视它。为了给你的用户设定基本规则，我们建议提供一份包含以下信息的引言：

- 文档涵盖什么内容。
- 你期望读者具备哪些先验知识。
- 文档不涵盖什么内容。

记住，你希望保持文档易于维护，所以不要在引言中试图涵盖一切。

下面这段文字以一个假想的文档发布平台 Froobus 为例，展示了上述列表中的想法如何作为概览呈现：

```markdown
本文档解释如何使用 Froobus 系统发布 Markdown 文件。
Froobus 是一个运行在 Linux 服务器上、把 Markdown 文件转换成
HTML 页面的发布系统。本文档面向熟悉 Markdown 语法的读者。
要学习该语法，请参见 Markdown 参考。你还需要能够在
Linux 终端中轻松运行简单命令。本文档不包含安装或
配置 Froobus 发布系统的信息。关于安装 Froobus 的信息，
请参见"开始使用"。
```

完成初稿后，把整份文档与你在概览中设定的期望进行核对。你的引言是否准确概括了你所涵盖的主题？你可能会发现，把这种审阅看作一种文档质量保证（QA）会很有用。

## 添加导航

为你的读者提供导航和路标，确保他们能找到正在寻找的东西，以及让他们摆脱困境所需的信息。

清晰的导航包括：

- 引言和小结部分
- 清晰、合乎逻辑的主题展开
- 帮助用户理解主题的各级标题
- 显示用户在文档中所处位置的目录菜单
- 指向相关资源或更深入信息的链接
- 指向下一步学习内容的链接

以下各节的提示可以帮助你规划文档中的标题。

### 优先使用基于任务的标题

选择描述读者正在处理的任务的标题。避免使用依赖陌生术语或工具的标题。例如，假设你在文档化创建新网站的过程。要创建网站，读者必须初始化 Froobus 框架。要初始化 Froobus 框架，读者必须运行 `carambola` 命令行工具。乍看之下，给指令加上以下任一标题似乎都合乎逻辑：

- 运行 carambola 命令
- 初始化 Froobus 框架

除非你的读者已经非常熟悉这一主题的术语和概念，否则一个更熟悉的标题可能更可取，例如 *创建网站*。

### 在每个标题下提供文字

大多数读者都欢迎每个标题下至少有一小段简短的介绍来提供一些语境。避免把三级标题紧挨在二级标题之后，如下例所示：

```markdown
## 创建网站
### 运行 carambola 命令
```

在这个例子中，一小段介绍可以帮助读者确定方向：

```markdown
## 创建网站

要创建网站，你运行 `carambola` 命令行工具。该命令
显示一系列提示来帮助你配置网站。

### 运行 carambola 命令
```

## 渐进式披露信息

对许多习惯于按自己的节奏通读文档的读者来说，学习新概念、新想法和新技巧可以是一种有回报的体验。然而，一下子面对太多新概念和新指令可能会让人不知所措。如果一份较长的文档在读者需要时渐进式地披露新信息，读者更容易接受它。以下技巧可以帮助你在文档中融入渐进式披露：

- 只要可能，试着在依赖它们的指令附近引入新术语和新概念。
- 打散大段大段的文字。为了避免单个页面上出现多个大段落，试着在合适的地方引入表格、图示、列表和标题。
- 打散大段大段的步骤。如果你有一串特别长的复杂步骤，试着把它们重新排列成更短的、解释如何完成子任务的列表。
- 从简单的示例和指令开始，然后逐渐加入更有趣、更复杂的技巧。例如，在一份创建表单的教程中，先解释如何处理文本应答，然后再引入处理多选题、图片和其他应答类型的技巧。
