这个选学单元对标点符号做一个快速复习。

## 逗号

编程语言对标点有明确的规定。相比之下，英语中关于逗号的规则有些模糊。作为准则，在读者会在句子中自然停顿的地方插入逗号。对于有音乐素养的人，如果说句号是一个全音符（semibreve）的休止，那么逗号大约是一个二分音符（minim）或四分音符（crotchet）的休止。换句话说，逗号的停顿比句号短。例如，如果你大声读下面这句话，你很可能在*just*这个词之前短暂停顿：
> C 是一种中级语言，在抽象层级上只比汇编语言高几步。

有些情况*必须*使用逗号。例如，用逗号分隔嵌入式列表里的条目，就像下面这样：
> 我们公司使用 C++、Python、Java 和 JavaScript。

你可能在好奇列表的最后一个逗号，也就是插在条目 N-1 和 N 之间的那个。这个逗号——被称为**序列逗号**或**牛津逗号**——是有争议的。我们建议补上这最后一个逗号，原因很简单：技术写作要求选择歧义最小的方案。话虽如此，我们其实更倾向于通过把嵌入式列表改写成无序列表来回避争议。

在表达条件的句子里，把逗号放在条件和结果之间。例如，下面两句话都把逗号放在了正确的位置：
> 如果程序运行缓慢，就试试 `--perf` 标志。
>
> 如果程序运行缓慢，那么就试试 `--perf` 标志。

你也可以把一段简短的说明或题外话夹在一对逗号之间，就像下面这个例子：
> Python，一种易用的语言，近年来获得了显著的发展势头。

最后，避免用逗号把两个独立的观点粘在一起。例如，下面这句话里的逗号犯了标点上的重罪，叫做**逗号粘连**：

不推荐
> Samantha 是位出色的程序员，她写了大量测试。

要用句号而不是逗号来分隔两个独立观点。例如：

推荐
> Samantha 是位出色的程序员。她写了大量测试。

### 练习

在下面这段文字的适当位置加上逗号：
> Protocol Buffers 有时被称为 protobufs 是我们团队的主要结构化数据格式。使用 Protocol Buffers 来表示存储和传输结构化数据。与 XML 不同 Protocol Buffers 是编译的。因此客户端高效地传输 Protocol Buffers 这导致了快速采用。

提示：大声朗读这段文字，在你听到短停顿的每个地方都加上逗号。

下面是一个可能的解决方案：
> Protocol Buffers**，**有时被称为 protobufs**，**是我们团队的主要结构化数据格式。使用 Protocol Buffers 来表示**、**存储**和**传输结构化数据。与 XML 不同**，**Protocol Buffers 是编译的。因此**，**客户端高效地传输 Protocol Buffers**，**这导致了快速采用。

## 分号

句号分隔不同的观点；分号联合高度相关的观点。例如，注意下面这句话里分号如何联合第一个和第二个观点：

推荐
> 更新配置文件后重新运行 Frambus；更新现有源代码后不要重新运行 Frambus。

使用分号之前，先问自己：如果把分号两边的观点对调，这句话还讲得通吗？例如，把前面的例子反过来仍然是一个*有效*的句子：
> 更新现有源代码后不要重新运行 Frambus；更新配置文件后重新运行 Frambus。

分号前后的观点必须各自是语法上完整的句子。例如，下面这个分号是*错误*的，因为分号后面的内容是一个[从句](https://developers.google.com/tech-writing/one/short-sentences#reduce_subordinate_clauses_optional)，而不是完整的句子：

不推荐
> 更新配置文件后重新运行 Frambus；而不是更新现有源代码后。

推荐
> 更新配置文件后重新运行 Frambus，而不是更新现有源代码后。

你几乎总是应该用逗号而不是分号来分隔嵌入式列表的条目。例如，下面使用分号是*错误*的：

不推荐
> 风格指南比月亮还大；比氧气还不可或缺；而且完全难以理解。

如本课前面提到的，技术写作通常更喜欢无序列表而不是嵌入式列表。然而，如果你真的更喜欢嵌入式列表，就用逗号而不是分号来分隔条目，就像下面这个例子：

推荐
> 风格指南比月亮还大，比氧气还不可或缺，而且完全难以理解。

许多句子会在分号后面立即放一个过渡词或短语。在这种情况下，在过渡词后面加一个逗号。注意下面两个例子中过渡词后面的逗号：
> Frambus 没有提供官方的开源字符串处理包；不过**，**其他开源项目提供了字符串处理包的子集。
> 即使看似微不足道的代码改动也可能导致 bug；因此**，**请写大量的单元测试。

### 练习

下面哪些句号或逗号可以用分号替换？

1. Python 是一种流行的编程语言。C 语言在 Python 之前很久就发展起来了。
2. 低 X 值的模型学习出现在上图。高 X 值的模型学习出现在下图。
3. 我很感激我的大显示器、强大的 CPU 和飞快的带宽。

#### 点击图标查看答案。

1. 你不能把 #1 中的句号换成分号，因为这两句话只是含糊地相关。
2. 你可以把 #2 中的句号换成分号，因为这两句话高度相关。
3. 你不能把 #3 中的逗号换成分号。用逗号分隔嵌入式列表的条目。

（实际结论：1 不能改成分号，2 可以改成分号，3 不能改成分号。）

## 破折号

破折号是引人注目的标点，充满标点的可能性。破折号表示比逗号更长的停顿——更大的停顿。对于有音乐素养的人，把逗号想成四分音符（crotchet）的休止，把破折号想成二分音符（minim）的休止。例如：
> C++ 是一种丰富的语言——一种需要大量经验才能完全理解的语言。

写作者有时会用一对破折号来框住一段题外话，就像下面这个例子：
> **Protocol Buffers**——常被昵称为**protobufs**——用一种高效又可扩展的格式编码结构化数据。

在前面的例子里，我们能用逗号代替破折号吗？当然可以。那我们为什么选破折号而不是逗号？凭感觉。凭艺术。凭经验。

### 连接号和连字符

考虑下表所示的水平标点符号：

| 名称 | 符号 | 相对宽度 |
|---|---|---|
| 破折号 | --- | 最宽（通常是字母 `m` 的长度） |
| 连接号 | -- | 中等（通常是字母 `n` 的长度） |
| 连字符 | - | 最窄 |

有些风格指南推荐在特定情况下使用**连接号**。然而，[Google 风格指南](https://developers.google.com/style/dashes#en-dashes)对连接号给出了这样的直率建议：
> 不要用。

**连字符**很棘手。在技术写作中，连字符连接某些复合词中的单词，例如：

- 自注意力（self-attention）
- N-gram

令人困惑的是，三个单词的复合词通常在第一个和第二个词之间有一个连字符，但在第二个和第三个词之间没有。例如：

- 决策制定系统（decision-making system）
- 浮点特性（floating-point feature）

对连字符拿不准时，查字典、术语表或风格指南。

> **注意：** 如果你就连字符咨询*多本*字典、术语表或风格指南，你可能会遇到不一致的情况。

## 冒号

在技术写作中，用冒号提醒读者后面会有一个列表或表格。换句话说，让[引出列表或表格的句子](https://developers.google.com/tech-writing/one/lists-and-tables#introduce_each_list_and_table)以冒号结尾。在下面这个例子中，注意引出列表的句子末尾的冒号：
> 考虑以下重要的编程语言：
>
> - Python
> - Java
> - C++

技术写作更喜欢无序列表或有序列表而不是嵌入式列表。话虽如此，你也可以用冒号来引出嵌入式列表，就像下面这个例子：
> 考虑以下重要的编程语言：Python、Java 和 C++。

并非所有嵌入式列表都需要冒号。例如：
> 我最喜欢的三种编程语言是 Python、Java 以及除 C++ 之外的任何语言。

## 括号

用括号来容纳次要的观点和题外话。括号告诉读者括号里的文字并不关键。因为括号里的文字不关键，一些编辑觉得值得放进括号的文字就不值得放进文档。作为折中，技术写作中要把括号的使用降到最低。

关于句号和括号的规则并不总是很清楚。以下是标准规则：

- 如果一对括号容纳了整个句子，句号放在后括号的里面。
- 如果一对括号结束一个句子但没有容纳整个句子，句号放在后括号的紧外面。

例如：
> （顺便说一句，Protocol Buffers 是很好的生日礼物。）
>
> 二进制模式依赖更紧凑的原生形式（本文档后面会介绍）。
