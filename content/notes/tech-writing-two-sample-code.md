好的示例代码往往是最好的文档。即使你的段落和列表清澈见底，程序员仍然更喜欢好的示例代码。毕竟，文字和代码是两种不同的语言，而代码才是读者真正在乎的东西。用文字来描述代码，就像用英语来解释一首意大利语的诗。

好的示例是**正确**且**简洁**的代码，你的读者能够**快速理解**、**轻松复用**，并且**副作用最小**。

## 正确

示例代码应满足以下标准：

- 能够无错误地构建。
- 能够完成它声称完成的任务。
- 尽可能达到生产就绪。例如，代码不应包含任何安全漏洞。
- 遵循特定语言的惯例。

示例代码是直接影响用户如何写代码的机会。因此，示例代码应当展示使用你产品的最佳方式。如果完成该任务有多种编码方式，请按照你的团队认为最佳的方式来编写。如果你的团队还没有权衡过每种方法的利弊，请花时间去做这件事。

始终测试你的示例代码。随着时间推移，系统会变化，你的示例代码可能失效。要像维护任何其他代码一样，准备好测试和维护示例代码。

许多团队把单元测试当作示例程序来复用，这有时是个坏主意。单元测试的首要目标是测试；示例程序的唯一目标是教育。

**代码片段（snippet）** 是示例程序的一小部分，可能只有一行或几行。以片段为主的文档往往会随时间退化，因为团队对片段的测试通常不像对完整示例程序那样严格。

### 运行示例代码

好的文档会解释如何运行示例代码。例如，你的文档可能需要告诉用户在运行示例之前执行以下活动：

- 安装某个库。
- 调整某些环境变量被赋的值。
- 在集成开发环境（IDE）中调整某些设置。

用户并不总是正确地执行上述活动。在某些情况下，用户更愿意直接在文档中运行（或试验）示例代码。（"点击这里运行这段代码。"）

写作者应该考虑描述示例代码的预期输出或结果，尤其是对于那些难以运行的示例代码。

## 简洁

示例代码应该简短，只包含必要成分。当一个 C 语言新手程序员想学习如何调用 `malloc` 函数时，给那个程序员一段简短的片段，而不是整个 Linux 源代码树。无关的代码会分散并迷惑你的读者。话虽如此，永远不要用坏习惯来缩短你的代码；始终把正确性置于简洁性之上。

## 易懂

遵循以下建议来创建清晰的示例代码：

- 选择描述性的类名、方法名和变量名。
- 避免用难以破解的编程技巧迷惑读者。
- 避免过深的嵌套代码。
- 可选：使用粗体或彩色字体把读者的注意力吸引到示例代码的特定部分。不过，要审慎使用高亮——高亮太多，读者反而不会聚焦于任何特定内容。

## 加注释

请考虑以下关于示例代码中注释的建议：

- 保持注释简短，但始终把清晰置于简洁之上。
- 避免为*显而易见*的代码写注释，但要记住，对你（专家）显而易见的，对新手可能并不显而易见。
- 把注释的精力集中在代码中任何不直观的地方。
- 当你的读者对某项技术非常有经验时，不要解释代码在*做什么*，而要解释代码*为什么*这么做。

你该把代码的描述放在代码注释里，还是放在示例代码之外的文字（段落或列表）里？请注意，复制粘贴一段代码片段的读者，不仅拿到代码，也拿到其中嵌入的任何注释。所以，把应该属于粘贴后代码中的描述放进代码注释。相反，当你必须解释一个冗长或棘手的概念时，你通常应该把文字放在示例程序之前。

> **注意：** 如果你必须牺牲生产就绪性来让代码更短、更容易理解，请在注释中解释你的决策。

## 可复用

为了让你的读者轻松复用示例代码，请提供以下内容：

- 运行示例代码所需的全部信息，包括任何依赖和设置。
- 能够以有用的方式被扩展或定制的代码。

拥有容易理解、简洁且能编译的示例代码是一个很好的开端。但如果它把你的读者应用搞崩了，他们可不会高兴。因此，编写示例代码时，要考虑到你的代码被集成到另一个程序中可能引起的任何潜在副作用。没有人想要不安全或极其低效的代码。

## 示例与反例

除了向读者展示*该做什么*，有时也明智地展示*不该做什么*。例如，许多编程语言允许程序员在等号两侧放空白。现在假设你在编写一份关于某种语言（如 bash）的教程，而这种语言不允许在等号两侧放空白。在这种情况下，同时展示一个好示例和一个反例对读者有好处。例如：

```
# 一个合法的字符串赋值。
s="The rain in Maine."
```

```
# 一个不合法的字符串赋值，因为等号两侧有空白。
s = "The rain in Maine."
```

## 有层次

一套好的示例代码展示**一系列复杂度**。

对某项技术完全陌生的读者，通常渴望简单的示例来上手。一套示例代码中的第一个、最基础的示例，通常被称为 [Hello World 程序](https://wikipedia.org/wiki/%22Hello,_World!%22_program)。掌握基础之后，工程师想要更复杂的程序。一套好的示例代码提供简单、中等和复杂示例程序的健康范围。

### 练习

下面哪一组示例函数适合支持一份向新手介绍函数概念的教程？

1. 下面这一组函数：
   1. 一个不接受参数也不返回任何值的函数。
   2. 一个接受一个参数但不返回任何值的函数。
   3. 一个接受一个参数并返回一个值的函数。
   4. 一个接受三个参数并返回一个值的函数。
2. 下面这一组函数：
   1. 一个接受三个参数并返回一个值的函数。
3. 下面这一组函数：
   1. 一个接受一个参数并返回一个值的函数。
   2. 一个接受三个参数并返回一个值的函数。

#### 点击图标查看答案。

最佳答案是 **1**。提供覆盖一系列复杂度的示例通常是最明智的选择——尤其是对新手而言。抵制住*急急忙忙*跳到非常复杂示例程序的诱惑，跳过新手渴望的初级和中级示例程序。
